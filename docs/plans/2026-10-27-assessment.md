# 수행평가 · 교사 권한 · 서버 모니터링 확장

## 목표
- 대회와 구분되는 **수행평가**를 만들고, 같은 수행평가를 **여러 반이 반별 회차**로 실시할 수 있게 한다.
- **교사** 권한을 만들어 교사가 대회를 제외한 수행평가를 직접 만들고 운영하게 한다.
- 수행평가 중 **부정행위 의심 행동**(화면 이탈, 붙여넣기, 급격한 코드 증가, 복사)을 기록하고 학생에게 기록 중임을 안내한다.
- 수행평가·대회 문제는 **기본 비공개**로 두고, 모든 회차가 끝난 뒤 공개할 수 있게 한다.
- 대회·수행평가 중 생기는 문제(채점 지연, 제출 이상, 접속 이상)를 **서버 모니터링에서 확인하고 조치**할 수 있게 한다.
- 관리자·교사 메뉴를 사이트 **헤더 아래 별도 줄**에 보여 준다.

## 범위 (포함 / 제외)
**포함**
- 수행평가(부모)와 반별 회차(각 회차 = 기존 대회 1개) 구조, 교사 권한(`teacher`)
- 반(`users.group_name`) 일괄 지정 화면
- 부정행위 감지 기록(`assessment_event`)과 학생 안내, 회차별 임계값 설정
- 수행평가 진행 중 결과 숨김(제출됨/컴파일 오류만 표시), 공개 처리
- 대회·수행평가 문제 기본 비공개와 "문제 공개" 처리
- 서버 모니터링 확장(경고 배너, 채점 큐, 제출 로그, 대회·수행평가, 접속·이상 징후, 재채점 조치)
- 헤더 아래 역할별 메뉴 줄

**제외**
- 채점 로직(`judge_client`, `judged`, `makeout.sh`)의 변경
- 반 테이블 신설(한 학생 여러 반 소속) — `group_name` 하나를 사용
- 다른 사용자 템플릿(`bs3`, `mdui`, `sidebar`, `sweet`, `bshark`)
- 붙여넣기·복사한 **내용** 저장(크기만 기록)
- 부정행위 감지 시 제출 차단(기록·안내만)

## 확정된 결정
| 결정 | 선택 | 근거 |
|---|---|---|
| 여러 반 실시 방식 | 수행평가(공통 문제) + **반별 회차**, 회차마다 대회 1개 생성 | 반마다 시간이 다르며, 기존 대회의 권한·채점·순위 로직을 그대로 써서 위험이 가장 작다 |
| 반 정보 | 기존 `users.group_name`(학생당 1개) | 채점 현황 필터·반 통계가 이미 이 값을 쓴다 |
| 교사 권한 범위 | 수행평가 생성·관리, 문제 작성·수정(자기 문제), 학생 반 지정, 자기 수행평가 모니터링·감지 기록, 자기 수행평가 재채점 | 사용자 요청 |
| 교사 간 공유 | 다른 교사 수행평가·문제는 **보기·복사만**, 수정·결과·감지 기록은 작성자만 | 같은 학년 문항 공유는 허용하되 평가 결과는 보호 |
| 문제 공개 시점 | **모든 회차 종료 후** 교사·관리자가 직접 공개 | 먼저 끝난 반을 통한 문제 유출 방지 |
| 공개 시 열리는 것 | 문제를 문제 목록에 추가, 학생 본인 결과 공개 | 순위·다른 학생 정답 코드는 공개하지 않음 |
| 진행 중 학생 화면 | "제출됨"과 컴파일 오류만 표시, 정답/오답·점수는 공개 전까지 숨김 | 컴파일 오류는 학생이 고쳐야 하므로 보여 줌. 판정 로직은 그대로, 표시만 바꿈 |
| 감지 항목 | 화면·탭 이탈(복귀까지 초), 편집기 붙여넣기(글자·줄 수), 급격한 코드 증가, 문제·코드 복사 | 사용자 요청 |
| 감지 대응 | 교사 기록 + 학생 안내("이 행동은 기록됩니다"), 제출은 막지 않음 | 오탐 시 학생 피해 최소화 |
| 감지 임계값 | 기본값 + 수행평가별 조정. 기본: 이탈 2초 이상, 붙여넣기 30자 이상, 2초 내 타이핑 없이 200자 이상 증가, 복사 20자 이상. 임계값 미만도 기록하되 의심 표시는 하지 않음 | 반·과제 성격에 따라 기준이 다름 |
| 수행평가 표시 방식 | `contest_type` 9번 비트(`$OJ_CONTEST_ASSESSMENT_BIT = 1<<9`), 대회 추가·수정 화면 옵션 목록(`$contest_locks`)에 추가 | 스키마 변경 없이 기존 옵션 체계 사용 |
| 문제 비공개 구현 | 문제 `defunct='Y'`. 대회 경로(`problem.php?cid=`)는 `defunct`를 보지 않으므로 대회·수행평가 안에서는 그대로 풀 수 있음 | 기존 컬럼만으로 구현(코드 확인함) |
| 교사 권한 저장 | `privilege` 테이블 `rightstr='teacher'` → 로그인 시 `$_SESSION[GSMOJ_teacher]` | 로그인 시 모든 권한 행을 세션에 싣는 기존 방식(코드 확인함) |
| 헤더 아래 메뉴 | 역할별 바로가기 + 진행 중 상태 배지. 관리자: 관리자 페이지·서버 모니터링·문제·대회·수행평가·사용자. 교사: 수행평가·내 문제·수행평가 모니터링·반 지정. 학생은 표시 안 함 | 사용자 요청 |
| 모니터링 범위 | 관리자: 전체(서버 자원·서비스 포함). 교사: 자기 수행평가의 채점 큐·제출 로그·감지 기록만 | 서버 정보·다른 반 기록 보호 |
| 모니터링 조치 | 선택 제출 재채점, 멈춘 제출 채점기 재호출, 대회 문제 재채점. 모두 확인 창 + 기존 `rejudge.php`와 같은 SQL | 사용자 요청(조치 가능) |
| 배포 | 5단계 PR로 나눠 단계마다 서버 확인 후 머지 | `main` 머지가 곧 운영 배포 |

## 데이터 모델
- `assessment_event` (생성 완료, 브랜치 `feat/assessment-foundation`에 정의): `event_id, contest_id, num, user_id, event_type(leave/return/paste/burst/copy), amount, line_count, place(problem/editor), ip, created_at`
- `assessment` (신규): `assessment_id, title, description, owner(user_id), settings(JSON: 임계값), published_at, created_at, defunct`
- `assessment_problem` (신규): `assessment_id, problem_id, num` — 회차들이 공유하는 문제 목록
- `assessment_session` (신규): `assessment_id, contest_id, group_name` — 반별 회차와 실제 대회의 연결
- 회차 대회: `contest_type |= 1<<9`, `private=1`, 참가자 = 해당 반 학생(`privilege cNNNN`), 관리자 = 교사(`privilege mNNNN`), 제목 "평가명 - 반"
- 시각: 웹의 DB 연결은 `include/init.php`에서 `SET time_zone='+8:00'`을 실행하므로 `in_date`(DATETIME)·`loginlog.time`·`NOW()`는 같은 기준이다. `judgetime`은 TIMESTAMP라 UTC로 저장되지만 읽을 때 연결 시간대로 바뀌므로 웹 연결 안에서는 보정 없이 비교한다. (DB 콘솔은 시간대를 맞추지 않으므로 값이 8시간 다르게 보인다)

## 구현 순서
1. **① 모니터링 확장**(독립): 경고 배너 → 채점 큐 → 제출 로그 → 대회 탭 → 접속·이상 징후 → 재채점 조치.
2. **② 헤더 메뉴 줄과 반 지정**: 기존 권한만으로 동작하도록 먼저 넣고, ③에서 교사 항목을 채운다.
3. **③ 교사 권한·수행평가·회차**: 테이블 → 권한 → 목록·작성·복사 → 회차·참가자 → 문제 소유 제한.
4. **④ 부정행위 감지**: 수신 엔드포인트 → 감지 스크립트 → 학생 안내 → 모니터링 수행평가 탭에 학생별 요약·이벤트 목록.
5. **⑤ 결과 숨김·공개**: 진행 중 표시 변경 → 공개 버튼(모든 회차 종료 확인) → 대회 문제 기본 비공개.

## 검증 계획
- 단계마다 `php -l`, 브라우저 스크립트는 `node --check`.
- 서버에서 임시 세션(관리자·교사·학생 각각)으로 확인하고 끝나면 세션을 삭제한다. 테스트 데이터(대회·수행평가·제출)는 만든 뒤 삭제한다.
- ①: 경고 배너 조건(채점기 중지는 확인하지 않고 큐 지연은 테스트 제출로 확인), 탭별 필터, 재채점 후 결과 갱신.
- ②: 관리자·교사·학생별 메뉴 줄 표시, 반 지정 후 `status.php?group_name=` 필터.
- ③: 교사가 대회 관리·다른 교사 결과에 접근하지 못하는지, 회차 참가자만 문제를 볼 수 있는지.
- ④: 문제 화면↔편집기 iframe 포커스 이동이 이탈로 기록되지 않는지, 붙여넣기·증가·복사 기록과 임계값, 분당 횟수 제한.
- ⑤: 진행 중 학생 화면(제출됨·컴파일 오류만), 공개 전후 문제 목록·결과, 일부 회차 진행 중일 때 공개 버튼 비활성.
- 사용자 화면 수동 확인: `/`, `/problemset.php`, `/problem.php?id=1000`, `/submitpage.php?id=1000`, `/status.php`, `/contest.php`, `/admin/`.

## 수동 절차 및 위험
- **DB 스키마**: `assessment_event`는 운영 DB에 이미 생성함. `assessment`, `assessment_problem`, `assessment_session`은 ③ 배포 시 `admin/update_db.php` 실행 또는 직접 생성이 필요하다.
- **권한**: 교사 계정에 `teacher` 권한을 부여해야 한다(권한 추가 화면 목록에 추가 예정). 교사는 다시 로그인해야 권한이 적용된다.
- **문제 기본 비공개**: 기존 대회 문제의 공개 상태는 바꾸지 않고, 이후 새로 넣는 문제부터 적용한다.
- **결과 숨김**: 화면 표시만 바꾸고 채점 결과(`solution.result`)는 그대로 저장한다. 표시 누락 경로가 있으면 결과가 노출될 수 있으므로 ⑤에서 결과가 보이는 모든 화면을 점검한다.
- **감지 오탐**: 브라우저 확장, 화면 잠금, IME 입력 등으로 의심 기록이 생길 수 있다. 기록은 판단 자료로만 쓰고 자동 제재하지 않는다.
- **시간대**: 사이트 PHP 시간대가 `Asia/Shanghai`(+8)로 설정되어 있어 한국 시각(+9)과 1시간 차이가 난다. 이 계획에서는 바꾸지 않는다(열린 질문 참고).

## 열린 질문
- 사이트 시간대를 `Asia/Seoul`로 바꿀지(바꾸면 기존 제출 시각 표시가 1시간씩 밀림, 별도 작업 권장).
- 반 이름 형식(예: `2-1`, `2학년 1반`) 통일 규칙.
- 교사가 만든 문제를 수행평가 없이 일반 문제 목록에 바로 공개할 수 있는지(현재 계획: 관리자만 가능).
